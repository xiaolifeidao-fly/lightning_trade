## 1. 任务目标

让 argus 的三个部署实例（`argus-single-1`、`argus-single-roc`、`argus-single-ives`）各自拥有**独立的配置发布链路**：一个实例发布配置，只有它自己重载，另外两个不受影响。

做完之后的变化：
- 新增 `argus_instance` 实例注册表，三份部署 properties 可以各导入一份配置；
- `argus_config_version` 按实例分域，每个实例各有一条 `published` 记录、各有一条独立的版本序列；
- Redis 配置键带实例命名空间，实例之间不再互相覆盖快照；
- `argus:config:changed` 广播消息带 `instanceId`，argus_single 只处理属于自己的消息。

## 3. 需交付的内容

### 3.1 实例注册表 `argus_instance`

新增实体 `ArgusInstance`：`instance_key`（唯一）、`instance_name`、`description`、`config_source`、`enabled`，纳入 `EnsureTable()` 的 AutoMigrate。

### 3.2 配置版本按实例分域

- `ArgusConfigVersion` 增加 `instance_key`；
- `idx_argus_single_published` 改为 `(instance_key, published_slot)`；
- `idx_argus_config_version` 改为 `(instance_key, version)`，`NextVersion` 按实例递增；
- Repository 的 `FindPublished` / `FindPublishedContext` / `FindByVersion` / `NextVersion` / `LoadSnapshot` / `LoadSnapshotContext` 全部带实例参数，`LoadSnapshot` 用实例键做版本归属校验。

### 3.3 Redis 键与广播按实例

- 键改为 `argus:config:{instanceKey}:snapshot` / `:version` / `:snapshot:{version}`；
- `WriteConfigSnapshot` / `ReadConfigSnapshot` / `PublishConfigVersion` 增加 `instanceKey` 首参，缺失时返回 `ErrInstanceKeyRequired`；
- `ConfigSnapshotEnvelope` 与 `ConfigVersionMessage` 增加 `instanceId`；
- `argus:config:changed` 仍是三实例共用频道，靠消息里的 `instanceId` 定向。

### 3.4 argus_single 侧过滤与分域读写

- `handleVersionMessage` 照 `handleControlMessage` 的范式补实例过滤；
- `Initialize` 强制要求 `argus.instance.id`，缺失直接启动失败（原来静默回落 `default`）；
- `loadCurrent` / `loadPublishedSnapshot` / `persistSession` 带实例键；
- 会话回写改为 `Manager.InstallSessionWriteBack()`，把实例键钉进钩子。

### 3.5 Service 与管理端接口带实例参数

- `GetPublished` / `SaveDraft` / `Publish` 及内部的 `mergePublishedSecrets` / `validateVersion` / `rollbackPublishedVersion` / `restoreRedisSnapshot` / `snapshotDTO` 带实例参数；
- 归档 SQL 加 `instance_key = ?`，一次发布只翻自己实例的 `published` 槽位；
- 管理端接口：`GET /argus-config/published` 支持 `?instanceKey=`，`POST /argus-config/drafts`、`POST /argus-config/versions/:id/publish` 支持请求体/query 传 `instanceKey`；新增 `GET/POST /argus-config/instances`。

### 3.6 实例键唯一性校验与重复告警

- `NormalizeInstanceKey` 限制 `[A-Za-z0-9_.-]{1,64}`（禁冒号与空白，避免 Redis 键被拼歪）；
- `RegisterInstance` 撞键直接拒绝并 `logrus.Warn`；
- `EnsureInstance` 幂等复用并告警，供导入命令反复执行；
- `DuplicateInstanceKeys` 兜底检测历史库缺唯一索引导致的重复，命中打 `logrus.Error`。

### 3.7 导入命令支持三份 properties

- `validateInstancePropertiesFile` 接受 `application[_suffix].properties`，其余文件名仍拒绝；
- `LoadMainConfigImport` 从 properties 的 `argus.instance.id` 读出实例键，写进 `ImportSummary.InstanceKey` 与 `SaveConfigRequest.InstanceKey`；
- 命令新增 `--instance` / `--instance-name`；导入前先 `EnsureInstance` 登记实例；已发布检查改为按实例判断。

### 3.8 历史数据迁移

- `EnsureInstanceScopedIndexes()`：GORM AutoMigrate 不会重建「同名但列已变化」的索引，因此显式查 `information_schema.statistics`，列集不符就 DROP + CREATE；
- `BackfillInstanceKey(defaultKey)`：把 `instance_key` 为空的历史版本行归到默认实例，由 Service 的 `EnsureTable()` 用 `argus.instance.default_key` / `argus.instance.id` 触发。

## 4. 约束与非目标

1. **不改策略判定逻辑**：`pkg/monitor`、`pkg/trade` 的开平仓判定一行不动。
2. **不做配置继承 / 模板**：三个实例各存一份完整配置，不实现「基线 + 覆盖」。
3. **不改前端**：`client/manager` 的 Argus 配置页不加实例切换器。为此管理端保留默认实例回落（见 §5），让现有前端在配置了 `argus.instance.default_key` 时照旧工作。
4. **Redis 旧键不做搬迁**：新键首次读取为空时，`loadCurrent` 会回落到 DB 的 published 版本并重写新键，属于既有降级路径，无需数据迁移脚本。
5. 保持仓库现有分层：Handler 只做绑定与响应，实例解析与告警放 Service，SQL 与索引迁移放 Repository。

## 5. 默认实例回落规则

`ArgusConfigService.ResolveInstanceKey(instanceKey)` 的优先级：

1. 显式入参（query `instanceKey` / 请求头 `X-Argus-Instance` / 请求体 `instanceKey`）；
2. 配置项 `argus.instance.default_key`，其次 `argus.instance.id`；
3. 注册表里恰好只有 1 个启用实例时，用它；
4. 都不满足则报错，**不允许猜**。

解析出的键还要过存在性与启用状态校验（`assertInstanceUsable`）。注册表为空时（首次导入前）放行并告警，避免 `argus-config-import` 自举死锁。
