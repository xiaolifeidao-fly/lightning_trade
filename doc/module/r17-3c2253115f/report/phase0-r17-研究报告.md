## 1. 结论与边界

原 Phase 0 的 cap 机制结论不变：主口径 ρ 未显著，rv 虽更强但方向是「高波动时更少打满 cap」，其可行动作会落入已否定的高波动降暴露方向。本次补到的 λ 事故样本只有 6 个有可见建仓决策的 episode，且横跨 cap 8/26/246 三个非随机参数包；它足以证明 λ 不再是零样本，却远不足以证明任何参数应按状态自动路由。

因此不进入 Phase 1，不实现自动路由，也不把高波动降 cap、紧止损、提前割肉或时间退出重新包装成候选。唯一保留的是后续以 **gate / trail 档位** 为对象、预注册且实例内控制混杂的研究；它不是本轮的上线建议。

## 2. 口径与前视偏差护栏

- `ρ(t)` 是过去 W 小时的去重盘口触发数；`rv(t)` 是过去 W 小时 1m 收益率总体标准差。每个盘口触发同时扇出到多个账户时按 `(ts, side, gap_bp)` 去重，避免 champion/challenger 把市场信号数两遍。
- 高状态为训练段 p80 以上、低状态为 p50 以下；阈值**没有**使用 8/18–8/21 观察段。状态在分钟栅格上连续 3 点才切换，所有标签都只取该时刻已发生信息。
- 收益不按 `closed_at` 分层。r10 的 `episode_entry.decided_at` 才是收益归集权威：每次实现盈亏按在场张数等比例摊回建仓决策。为避免当前无 MySQL 授权时伪造 PnL 分层，本报告不从 JSONL 重算 PnL；已由 r10 报告确认 8/18–21 的决策日与平仓日差异可达 191.27U。
- λ 的单位是「首次可见建仓决策形成的已出场 episode」。窗口开头没有可见 `open` 的截断 episode 不进入分子或分母；不能用其平仓时刻给它补一个状态。

## 6. 是否立项

**判定：不立项自动按行情路由参数（关闭）。**

理由：

1. 原 Phase 0 的可复现主结论仍未被推翻；ρ 与 rv 不是同一状态变量，不能拿较显著的一格替代预注册主口径。
2. λ 的 6 个可归集兜底提供了新的风险监测信号，但样本量、参数混杂和单一暴涨窗口都不满足作路由决策的门槛。
3. 决策归集护栏已经由 r10 落表；按平仓时刻补一张状态收益表会重造已知伪影，故本轮拒绝这种“显著性”。
4. trend_gate 当时未上线，重跑是反事实而非实测效果；它只保留为下一轮单变量、实例内 OOS 的 gate 研究对象。trail 档位同理，尚无合格的状态随机/对照设计。

- 自动路由仍不在范围内；任何新候选只能先走事件级/频率级回测与人工审批，绝不自动下发线上配置。

## 8. 数据限制

- 当前工作区的本地 MySQL 对 root 无免密访问，且没有获授权的事件库 DSN；为了不从配置或聊天记录提取凭据，本报告采用回灌真源离线复现。数据库可访问性是成品测试阶段需要补的环境条件，不是可以靠猜凭据绕过的问题。
- 训练档案由 6/28–8/16 的多个历史快照构成，8/9、8/17 等日期没有事件档案；rv 连续但 ρ 在档案空白处会自然衰减。因此 ρ 结果比 rv 更脆弱，不能被用作放宽结论的理由。
- trend 重跑使用 1m close，实时实现使用信号 tick 与完整 warmup；结论严格限于“反事实可拦截面”。
