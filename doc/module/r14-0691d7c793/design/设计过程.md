## 1. 需求怎么理解

本任务把已经具备的事件级回测、参数组批量扫描和后台寻优，变成两个能让研究/运维人员**看见证据、而非只看一个漂亮数字**的管理端页面：

1. `/argus-backtest` 以“所选实例 + 账户的已发布生产参数”为基线，编辑并批量提交的是**参数差异**；结果必须按事件级、频率级精度拆开，展示累计已实现净值、出场分布、与基线的同精度 diff 和逐笔明细。
2. `/argus-optimizer` 显示服务端冻结的搜索空间、降噪协议和三关阈值，实时读取粗网格/精算进度，逐格展示三关的独立结果、收益/回撤前沿及无解分支；不能把中位收益最高的一格称为“最优参数”。
3. 页面要明确两条易被误读的回测限制：不能从 1m K 线推导盘口信号（缺 mark price 且 28.7% 的信号分钟内会触发至少两次）；1m 仅用于持仓路径回放，`peakPct` 偏高、同 bar 止盈/止损冲突按不利方向结算。
4. “带这组参数去发布”只能将可映射的生产参数写入 `argus-config` 的草稿预填 URL。它不得发布、热加载、修改配置版本或控制进程；回测专用参数必须明确不映射。

需求级文档还要求：阈值变化自动降为频率级，跨精度不得比较 PnL；寻优的三关必须在发起时锁定、允许 0 格通过的无解结论；OOS 结果需与 in-sample 分开。以上不是展示文案，而是页面数据流和交互边界。

## 3. 方案比较与选择

### 3.1 页面是否重新计算研究结论

1. **浏览器按净 PnL 排全局榜并自行判断精度**：实现快，但会把频率级 λ 和事件级 PnL 混排，也会复制服务端规则并产生静默漂移；否决。
2. **后端返回的 `groups[]` 为唯一的比较结构，前端仅按组渲染**：事件级/频率级从数据形状就隔离，`metricDiff` 缺失时显示 `diffBlockedReason`；选中。
3. **前端重新计算寻优三关或从单路径/散点挑“最高收益格”**：破坏“发起时锁定”的可审计性，且与 16 路径分布的设计目标相反；否决。页面只显示 `okSign`、`okBear`、`okDd`、`passed` 与服务端生成的前沿标记。

### 3.2 是否按 1m K 线推信号

1. **K 线逐 bar 反推**：数据中没有 DeepCoin mark price，且分钟内多次信号会被压缩；会制造貌似精确的结果；按需求明确否决。
2. **用 `strategy_event` 真实触发点回放，阈值改动由 `dev_sample.DevCross` 给 λ**：与已有引擎、fidelity 判定和需求口径一致；选中。页面把两个精度等级的含义、限制和禁止比较直接展示在表格上方。

### 3.3 “带去发布”链路

1. **直接调用配置草稿/发布接口**：会让回测或寻优页面变成一键上线入口，违反任务非目标；否决。
2. **把所有回测参数都塞进配置页**：`capOverride`、过冲、费率、bar 内口径等是研究参数，根本没有生产落点；会让用户以为已发布生效；否决。
3. **仅转换明确的 `configParamKey`，通过既有 URL 预填进入配置页**：配置页会再按实例、账户、币种解析，并要求人工审阅/发布；选中。不可映射时弹出明确提示。

### 3.4 图表实现

1. **重引入一个统计图表包**：增加依赖且与需求指定的图表库不一致；否决。
2. **累计净值使用 lightweight-charts；统计前沿使用内联 SVG**：时间轴曲线享受统一 hover/缩放和墙钟口径，非时间序列散点不强行伪装成价格图；选中。

## 5. 影响面与兼容性

- 两个页面都是新增路由；已有 Argus 页面、已有回测详情接口和历史回测页面的行为不变。
- 批量回测的轮询只在 `pending/running` 期间进行；寻优同样只在活跃状态轮询，避免常驻请求。
- 生产基线、搜索空间、协议、阈值和批次数据都由服务端返回；前端不会用当前配置覆盖历史批次的冻结快照。
- 页面主动区分“已实现净值”与未平仓浮动，主动标示频率级“只产 λ，不产 PnL”。
- 权限 SQL 沿用项目已有 r7/r12/r13 的模板，默认变量是 `@role_id = 1`；执行到真实数据库前必须由环境负责人确认目标角色。SQL 本身尚未执行，不会改变任何数据库状态。

## 7. 风险、遗留与测试交接

1. 真实 8/18–8/21 数据、已发布 `argus_config` 和 r4/r6 灌入的 `strategy_event` 在本轮不可用，因此没有实际提交回测/寻优任务。成品测试应选择一个已导入实例，打开两页，检查生产基线、批次进度、事件级信号数与真实触发数一致，并确认阈值变化组只显示频率级 λ。
2. r16 已记录的基线兜底限制仍存在（如部分账户级配置尚无 DB 列、趋势闸可能按关闭回落、net 形态反向门控恒启用）。页面显示服务端 `baseline.notes` 与 `fidelityNote`，测试不得忽略这些提示。
3. 本任务只生成权限 SQL；未获得数据库连接与角色确认，未执行该 SQL。执行前确认 `@role_id`，再按 r7/r9/r12/r13 的前置资源 SQL 一起核对。
4. “带去发布”应验收为：跳转后只出现参数草稿和既有配置页的人工确认流程；不应产生新发布版本、Redis 广播或进程控制调用。研究专用参数应被明确跳过而不是静默填入。
5. 权衡前沿是统计空间的可视化，不等于结论；无解卡片必须在 `passedCellCount = 0` 时出现，且页面上不得出现“最优参数”措辞。
