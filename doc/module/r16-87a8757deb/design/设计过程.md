### 1.2 我对任务的复述

任务的重点**不是"多跑一些参数组"**——那是 r11 已经交付的能力。重点是把"怎么才算知道一组参数更好"这件事机械化：

1. **一格的产出不是一个 PnL，是一束路径上的分布**。16 条抖动路径 = {bar 模式 close/悲观} × {起点偏移 0-3 天} × {信号 5% 随机丢弃：不丢/丢(种子1)}，落库中位数 + IQR + 符号一致率。
2. **判定标准必须先于结果存在**。三关（一致率 ≥ 0.80、熊市月净 p10 ≥ 阈值、p90 回撤 ≤ DD_max）在发起时锁定，跑完不可改。
3. **允许"没有答案"**。一格都不过时输出权衡前沿 + 被支配的现行配置，不放宽标准硬凑。
4. **粗网格 → 自动收敛精算格**：粗网格省算力，判定只在精算阶段做。
5. 附带的口径要求：费用按 0.012%/边、兜底过冲 +5 ROI 点、按 episode 切块做情景 bootstrap、OOS 标注 in/out-of-sample、提示规模不变性破缺。
6. 不做：不改线上参数、不做贝叶斯/遗传。

任务说明给的真实反例（`study_fine.csv`）就是验收的抓手：`net(15,400)` 中位 +79.9U 但一致率 0.69；现行 champion `net(15,300)` 一致率 0.56。**按 PnL 排序会把这两格排在很多稳健格前面**——所以"排序口径"本身也是交付物的一部分。

### 2.2 金标准脚本里那些"文档没写"的口径（决定能不能对上数）

逐行读 `backtest_capsf_study.py` 才拿到的事实，每一条都影响数值：

1. `FINE_PATHS = [(p, off, seed) for p in (False,True) for off in (0,1,2,3) for seed in (None,1)]`
   → 路径顺序是 **evalMode → offset → seed**。bootstrap 的重采样池按路径序拼接，**顺序一变分位就变**。
2. `pnl28 = pnl * 28 / days`，`days = n_bars / 1440`，`n_bars` 只数 `dt >= start` 的根。
3. 期末浮动用**整个窗口最后一根**的收盘价（偏移只切前端，末根不变）。
4. `sign = #{pnl28 > 0} / N`（严格大于 0）。
5. `mean_loss = |mean(全路径合池的兜底平仓 pnl)|`，`pnl` 是**毛盈亏、不含手续费**（`close_book` 里 `pnl = pnl_per_contract * size`）。
6. `λ_bear`：逐路径 `单边日上的兜底次数 / 整窗口单边日数 × 30`，再取**中位数**。
   → 分母是**整窗口**的单边日数，即使偏移路径只覆盖窗口的一部分。这是一处**已知偏差**（分子少了分母没少 ⇒ 偏移路径的 λ 偏低），但它是校准口径，改了就与 `study_fine.csv` 对不上。
7. `p90dd = sorted(mdd)[min(n-1, int(n*0.9))]`——**不是插值分位**。16 条路径 → 取第 14 位。
8. `budget = λ_bear × mean_loss`；`stack = max over paths`；`fee = median over paths`。
9. 熊市月 bootstrap：把**全路径的单边日 ΔMTM** 合池，`random.Random(42)`，2000 次各抽 30 天求和，`p10 = sums[200]`、`p50 = sums[1000]`。
10. 5% 丢弃：`random.Random(seed)` 后 `rng.random() >= 0.05` 逐条消费随机流，**在起点偏移之后**执行。
11. 日标签在**整个窗口**上算一次，全路径共用；`o` 取当日首根开盘、`c` 取末根收盘。
12. 研究本金 `E_CAP = 375.73`、`EFF_TAKER = 0.00012`、`OVERSHOOT = 5`、cap 走**固定上限**（不走 cap 公式）、`order_size = 1`、trail 固定 champion 值。

另外一条**方法学层面的不一致**（很重要）：设计文档 §3.2 要求"按仓位生命周期切块（episode 对齐，避免切断持仓）"，但脚本实际实现的是**日级 iid 重抽**；§10.3 第 1 条自己承认了这点并指出它"对低 λ 配置偏悲观（把稀有损失日按 iid 重抽，高估尾部）"。**任务说明写的是"按 episode 切块"，验收写的是"与 study_fine.csv 逐格吻合"——这两条只有同时实现两种口径才能都满足**（见 §3.4）。

## 3. 考虑过哪些方案

### 3.1 怎么保证"与 study_fine.csv 逐格吻合"（本轮最关键的一个决定）

协议里有两处随机：5% 信号丢弃、情景 bootstrap 重采样。Go 的 `math/rand` 与 CPython 的 `random.Random`（MT19937 + `getrandbits` 拒绝采样）序列完全不同。

| 方案 | 做法 | 代价 / 风险 | 结论 |
| --- | --- | --- | --- |
| A. 用 `math/rand`，验收放宽成"数量级接近" | 最省事 | 16 条路径里 8 条带丢弃，**丢的不是同一批信号** ⇒ 中位数、一致率、λ、分位全都只能"大致接近"。验收第 7 条的"逐格吻合"退化成"看上去差不多"，而这条验收正是**整套方法学是否被正确移植**的唯一硬证据。一旦以后引擎某处口径漂移，没有任何测试会红 | ❌ 决定性缺陷 |
| B. 加大 bootstrap 抽样次数以压低蒙特卡洛误差 | 2000 → 20000 次 | 只解决 bootstrap，**完全不解决信号丢弃**（那是确定性的集合差异，不是抽样误差）。而且改抽样次数本身就偏离了金标准口径 | ❌ 治不了病根 |
| C. 去掉带丢弃的 8 条路径，只跑 8 条确定性路径 | 协议缩水成 8 条 | 直接删掉一个抖动轴：信号丢弃打掉的正是"结论依赖某几次特定触发"这类脆弱性，而这是均值回归累加器最典型的失效模式。且路径数腰斩 ⇒ 一致率的分辨率从 1/16 掉到 1/8，恰好卡在 0.80 决策线附近 | ❌ 削弱方法学本身 |
| **D. 移植一份 CPython 兼容的 MT19937**（选中） | 按 `_randommodule.c` + `random.py` 实现 `random()` / `getrandbits(k)` / `choice` 的下标 | 服务代码里多一份"自研 RNG"（约 130 行，纯函数、零依赖、自带测试向量），需要向后来的读者解释它为什么存在 | ✅ 把校准从"大致接近"变成**可测试的硬门槛**：逐格 1e-6 精度对上 `study_fine.csv`。而且这段代码天然稳定（MT19937 三十年没变过），维护成本接近零 |

选 D。实测结果：`TestStudyMatchesGoldenFineGrid` 一次通过，10 格 × 9 个统计量全部落在 1e-6 内。**这条测试同时钉住了 r8 的引擎口径、路径展开顺序、丢弃随机流、λ 分母口径、p90 取分位方式、bootstrap 抽样序列**——任何一处漂移它都会红。这是本轮最有价值的产出之一。

代价我如实记在代码注释里：这份 RNG **只用于研究口径复现，不用于任何安全场景**。

### 3.3 三关阈值怎么"预注册"

任务说明的原话是"阈值发起时锁定、跑完不可改"。

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A. 写在配置/常量里 | 简单 | ❌ 不同账户本金不同（研究本金 375.73U vs 实际账户 120U/414U），绝对阈值必须按各自本金派生；且"锁定"这件事无从审计 |
| B. 请求带阈值，判定时用请求里的值 | 灵活 | ❌ 判定时才读 = 跑完可以换标准，等于用同一份数据既定标准又选参数。本任务的核心就是要挡住这件事 |
| **C. 创建时写 `gate_snapshot` + `gate_locked_at`，执行期任何路径都不写这两列**（选中） | 阈值以 JSON 冻结落库，锁定时刻随详情回显 | ✅ 机械保障：`UpdateStudyConclusion` 等执行期方法的 `Updates` map 里**根本没有**这两个键（代码注释里点明了这是刻意的）。集成用例断言执行前后 `gate_locked_at` 逐字不变 |

阈值本身支持两种给法：优先给百分比（`riskEquity` + `bearBudgetPct` + `ddMaxPct` + `signMin`）由服务派生绝对值；也可以直接给绝对值以复现历史标准（−56U / 94U）。缺省口径下 `Describe()` 会说明"由 E/B_month/DD_max 派生"，显式给时说"显式给定"。

> 这里踩到一个真 bug 并修掉了：`Gates.Normalize()` 原先按"两个绝对阈值是否为零"重算 `Derived`，导致**二次归一化会把派生阈值误判成显式给定**（阈值冻结成 JSON 落库、OOS 任务读回来再归一，走的正是这条路），`Describe()` 里那句审计说明就变成假话。改成"只置不清"并补了 `TestGatesNormalizeIsIdempotent`。这个 bug 是 OOS 集成用例（断言 `gate_snapshot` 逐字相同）先发现的。

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A. 只做 day_iid（照抄脚本） | 校准能对上 | ❌ 任务说明"按 episode 切块"没落实；而且 §10.3 已指出它高估尾部、对低 λ 配置偏悲观——照抄就是把一个已知偏差固化成唯一口径 |
| B. 只做 episode_block（照文档原意） | 方法学更正确 | ❌ 与 `study_fine.csv` 不可比，验收第 7 条无法验证 |
| **C. 两种都实现，`bootstrapMode` 可选，缺省 day_iid**（选中） | 缺省用金标准口径（可校准），`episode_block` 作为设计原意口径可选 | ✅ 两条要求同时满足；而且**把 §10.3 那个"偏悲观"的偏差从一句文档结论变成可量化的对照**（同一格换口径跑一次就能看出高估了多少）。缺省选 day_iid 而不是 episode_block，是因为"能与历史结论比对"在本轮的优先级高于"口径更优"——第一版就换口径会让所有历史结论失去参照 |

`episode_block` 的实现：切点判据是"日界（次日 00:00，按 K 线时间戳所在时区）不落在任何持仓生命周期区间**内部**"（端点算空仓，刚平完就是切点）；净仓模式同一时刻只有一本仓，双向模式两侧区间先合并；未平仓（`Open=true`）视为持有到时间轴尽头，之后任何日界都不再是切点。块按天数抽到 ≥ 情景月长度后，把合计**归一到情景月天数**（块长不整除，不归一会让长块占优的情景系统性偏大）。

情景从 1 个扩到 3 个（熊市 / 震荡 / 混合），因为任务说明明确要"熊市月/震荡月/混合月"；脚本只算了熊市月。三个情景各起一条**新的**RNG 流（同种子），保证熊市月的抽样序列与"只算熊市月"时逐字一致。

### 3.5 "粗网格 → 自动收敛精算格"的收敛规则

金标准里这一步是**人工**的（脚本 `fine cells.txt` 由人挑 10 格）。要自动化就得给一条明确规则，而这条规则本身有过拟合风险。

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A. 按粗网格中位 PnL 取前 K | 直观 | ⚠️ 单独用不行：4 条路径的一致率只有 5 档，纯按中位 PnL 筛，**低幅但极稳的格子**（恰恰是三关最可能放行的那一类）会被筛掉 |
| B. 先在粗网格上跑三关，过关的进精算 | 看起来更"科学" | ❌ **把判定下沉到了 4 条路径**。一致率 0.75 与 0.80 在 4 条路径上根本无法区分，而那就是决策线。判定必须只在精算阶段做 |
| **C. 前 K 名 ∪ 粗网格全路径为正的格 ∪ 强制纳入现行配置格，再按 gate 副轴展开**（选中） | 三条来源合并去重 | ✅ ① 前 K 名控算力；② "全路径为正"补上 A 的漏洞；③ **现行配置格强制纳入**——"现行配置是否被支配"是本任务必须回答的问题（§10.3 第 2 条），它不能因为排名靠后就缺席；④ gate 副轴留到精算再展开（§10.2 的副轴发现 gate 20→8 让 (26,400) 从 +142.7 抬到 +168.7 就是这么来的），粗网格从 110 格省回 55 格 |

代码里把这条规则的性质写清楚了：**收敛不是判定，它只是省算力的筛选**。`Converge` 返回的 `Note` 逐条交代"为什么选这些格"，随任务落库并在详情里回显。超出 `MaxCells` 时把被丢掉的格子键列进 `Dropped` —— 静默截断会让"覆盖了整个空间"这句话变成假的。

### 3.6 OOS 纪律怎么落地

任务说明只要求"标注 in-sample/out-of-sample"。但只加一个字段的话，这个标注完全靠请求方自觉。

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A. 只加一个 `sampleKind` 字段由请求方声明 | 最小实现 | ⚠️ 满足字面要求，但标注可以随便填，"不重新调参"这条纪律没有任何约束力 |
| **B. 加 `oosBaseStudyId`：继承基准任务的冻结阈值/协议/精算格，只换窗口，并校验窗口起点晚于阈值锁定时刻**（选中） | 服务端强制 | ✅ 直接把"参数锁定后不再调参，用锁定之后新进的信号流每周复算"变成可执行的机制：给了 `gates` 或 `fineCells` 一律**报错**（改阈值/重选格就不是 OOS 验证了）；窗口起点早于锁定时刻直接拒绝并说明"这段数据在定参数时就见过"。`sampleKind` 由服务端判定，不由请求方声明 |

这比字面要求多做了一点，但它是"OOS 纪律"这四个字唯一有意义的实现方式——否则标注只是装饰。

### 3.7 结果怎么排序（防止把噪声排在前面）

这是任务说明那句"按 PnL 排序会选出纯噪声格子"的直接落点。

- ❌ 按 `medPnl28` 排：`net(15,400)`（中位 79.9 / 一致率 0.69）会排在很多稳健格前面。
- ❌ 不排序、让前端排：把护栏交给调用方 = 没有护栏（r11 §3.5 已经论证过这一点）。
- ✅ **先按通过的关数降序，再按中位 PnL 降序**，未跑通的行沉到末尾；粗网格与精算格**分两段返回**，接口层不给一张跨阶段的全局榜。单测 `TestSortOptimizeRowsPutsVerdictBeforePnl` 用一个"中位 500 只过 1 关"和"中位 80 过 3 关"的对照钉住这条口径。

DTO 里**刻意没有** `netPnl` 这类单值字段：给一个"该格的 PnL"就是在邀请人按点估计排序。

### 3.8 被否决的其他想法

- **把 `signal_threshold` 加进搜索空间**：改它会把精度降到频率级（只能推 λ(θ)、推不出触发时刻，见 `fidelity.go`），与事件级格子不可混排比较。放进来就等于在同一张榜里混两种精度，正是需求大纲 §3.3 禁止的。搜索空间因此恒产出事件级格子；详情接口仍保留"发现频率级格子就点名警告"的分支，防止有人从 `baselineParams` 侧偷偷改进来。
- **把 trail 8 个旋钮加进搜索空间**：§3.3 明确"固定 champion 值防组合爆炸，列二期"。
- **加"高波动 → 降低暴露"类的轴**：需求大纲 §3.4 把它归为 burst throttle 的变体，**已被实证否定，不得重跑**（T1 +61U vs 基线 +168.7U）。
- **贝叶斯优化 / 遗传算法**：任务说明明确不做。几十格网格足够，且可解释性更重要——寻优的产出要能回答"为什么是这一格"，进化算法答不上来。
- **让寻优自动把候选参数发布到 Redis / 写回配置**：需求大纲 §2.2 与本任务"不做"都明确禁止。候选的上线路径是人工在小额账户跑 challenger，通过后晋升。
- **在结论里给"推荐参数"**：`Conclude` 的措辞受单测约束（`TestConcludeNoSolutionAndDominatedIncumbent` 断言正文里不出现"最优参数/最佳参数"）。有候选时的措辞是"它们只是「没被三关否掉」，不是「最优」"。
- **参数非法的格子直接从搜索空间里剔除**：实例3 的 `order_size=10` 会让 cap 5/7 的格子物理上开不进一张。静默剔除会让"搜索空间覆盖了 55 格"这句话变成假的。改为建成 `skipped` 状态（**不是 failed**）并带上实盘校验器的原文，计入 `skip_cell_count` 单独统计。
- **λ_bear 直接改用无偏分母**：会与 `study_fine.csv` 对不上。保留 `lambdaDenom: window|path` 两种口径，缺省 `window`（金标准），偏差写进每格的 `notes`。

### 4.5 若干实现细节上的取舍

- **单格内的路径顺序跑**，并发放在格级。一格的统计量必须来自同一批路径；拆到路径级并发只会放大内存而不提速（格级已能吃满 CPU）。
- **偏移路径不灌种子仓**。种子仓是"窗口起点那一刻的旧仓"（r8 的 `SeedFromSignals` 从窗口内第一条带净仓快照的拦截事件推出），把它原样搬到偏移三天之后等于凭空造出一个当时可能早已平掉的仓位。金标准脚本本来就是空仓起步。
- **单条路径失败不废掉整格**（典型：偏移过大导致没有 K 线），但必须在该格的 `notes` 里记下"只跑通 m/n 条路径，一致率的分辨率因此下降"。全部路径都失败才算该格失败。
- **收敛与判定统一走"落库再读回"**，不用内存里的结果。理由是断点续跑时已 `done` 的格子不会重跑，那时唯一的真值就是库里的行；两条路径共用同一份重建逻辑（`cellStatsFromRow`），才不会出现"首次执行"与"续跑"算出不同的收敛结果。
- **统计量落库前统一 `RoundTo(_, 8)`**，避免 JSON 里出现 `1e-17` 这类浮点噪声位被当成有效数字读。
- **日块切点的时区显式传入**（`BuildMtmBlocks(..., loc)`），取自 K 线时间戳自身的 Location。写死 `time.Local` 会让"次日 00:00"在非 +08 环境或 UTC 标签的测试数据上错 8 小时，切点全错位——这正是需求大纲反复强调的那类隐蔽错误。

### 5.2 测试覆盖的行为

**金标准校准（2 条，最硬的证据）**

1. 10 格逐格吻合；顺带断言输入本身没被改动过（1459 信号 / 33196 根 / 11 单边日 + 7 震荡日）与协议展开 16 条路径。

**CPython RNG（3 条）**：`random()`（种子 1/42/12345）、`getrandbits(7)` 与 `getrandbits(32)`、`choice(range(11))` 的下标序列。

**方法学单测（16 条）**

- 精算协议展开 16 条路径且**标签逐条对上金标准顺序**；粗网格 4 条且不丢信号；零值协议补成金标准缺省，未知 `bootstrapMode` 落回 `day_iid`。
- 日标签三态（含"trend 不分涨跌"）与计数/清单。
- **持仓跨日界时不切块**；空仓日界切块；未平仓之后不再切块。
- 阈值派生出 §10.2 的两个历史数、显式阈值不被覆盖、**`Normalize` 幂等**（§3.3 那个真 bug 的回归用例）。
- `Judge`：三关全过；**中位 79.9 但一致率 0.69 的噪声格被否**；**熊市池为空按不通过计**；参考项（频率预算）不影响三关结论。
- 缺省空间展开 55 格、含 cap=∞ 对照格、gate 恒 20。
- `Converge`：前 K 名 + 全路径为正的补录 + **强制纳入现行配置格**；gate 副轴展开且同格相邻；**超限截断要发声并列出被丢掉的格子**。
- `Conclude` 无解分支：用 `study_fine.csv` 的真实数字验"现行 net(15,300) 被脊线两格全面支配"、**正文不出现"最优参数"**、必须出现"权衡前沿"与"OOS"、被支配的格不可能在前沿上；候选分支必须说明"只是没被否掉"且"不自动下发"。
- 规模不变性：120U 本金装不下 cap=26（破缺）、414U 装得下。
- 中位数走 Python `statistics.median` 口径、分位走金标准的"取 int(n*q) 位"口径。
- `RunPath`：同种子丢弃可复现、丢弃比例接近 5%、偏移路径少 1440 根、**偏移超窗口报错而不是静默给空结果**、偏移路径不沿用种子仓。
- `AggregateCell` 必须把口径说明与已知偏差一起带出来；空格子不崩但说清统计量无意义。

**编排层单测（8 条）**：寻优费用口径覆盖（显式给了则尊重）、非法格建成 skipped 且参数快照完整、现行配置格三种来源、阈值本金取基线 risk_equity（120U × 15% = −18U）、粗网格沿用精算的费用/情景口径、**OOS 继承冻结快照且忽略请求里的重调参**、并发数归一、**判定优先于收益的排序**、任务级提醒的 8 个必备要点、规模破缺文案、缺省预览（55 格 / 16+4 路径 / 预估 540 次回放）。

**真实 MySQL 集成（5 条）**

1. 两张新表的 47 + 55 列全部建出，且既有回测表的列一个不少。
2. 端到端（显式精算格）：跑通 → **`gate_locked_at` 执行前后逐字不变** → 回放次数 = 格数×路径数 → 数据事实（3 触发 / 60 根，与 r8/r11 用例同一份输入互相对照）→ **熊市不可估计时该关不放行** → 现行配置格被标出 → 详情返回冻结快照/前沿/规模核查/警示 → 结论正文无"最优参数"。
3. **粗网格 → 自动收敛**：4 粗格 → (top2 + 现行) × gate 2 档 = 6 精算格 → 20 次回放；`convergeNote` 含三条来源说明；不在搜索空间里的现行配置格确实被强制纳入且只标 1 格；**粗网格的行不带三关判定**。
4. 参数非法的格子建成 skipped、不阻断其余格、不计进失败、原因引用实盘校验器原文。
5. OOS 纪律：拒绝"定参数时见过的窗口"、拒绝换阈值、拒绝重新选格；合法 OOS 继承阈值快照与锁定时刻、继承精算格、`sampleKind` 由服务端判定。

### 5.3 关于 `strategy/optimize/` 那个中断产物的处理

如 §2.4 所述，`server/service/trade/strategy/optimize/` 是本任务早前一次中断执行留下的引擎层半成品：**未入库、无人 import、零测试**，抖动与 bootstrap 用 `math/rand`（结构上无法复现 `study_fine.csv`），且它注释里指名的编排层文件在本轮之前并不存在。

留着它会在树里并存两套寻优引擎，注定漂移且误导后来的读者。处理方式：**先完整拷贝到 `/tmp/r16-aborted-optimize-pkg/` 保底，再从工作树移除**，随后重跑三模块编译与全部测试确认无引用。它是本任务自己的中断产物（不是别的任务的交付），所以清理属本轮范围；因为是 untracked，删除不影响任何已入库文件。

它的两个想法我在本轮实现里保留了：`IsControl`（现行配置对照格 → 我的 `is_incumbent` + 强制纳入收敛）、episode 对齐切块（→ `BootstrapEpisodeBlock`，作为可选口径）。分歧只在缺省 bootstrap 口径：它默认 `episode`（设计原意），我默认 `day_iid`（可与 `study_fine.csv` 校准），理由见 §3.4。

### 5.4 尚未验证的

- **真实 8/18–8/21 数据集上的完整 55 格扫描**：需要 `strategy_event` 已由 r4/r6 灌入的库，本轮环境里没有该数据。金标准校准用的是 `signals_canonical.csv` 直接喂引擎（绕过 DB），验的是方法学；"从 DB 取真实事件流跑完整扫描"属成品测试阶段。
