# r15-27b9e2f39a · Argus 总览页、实例对比页与菜单重组设计过程

> 动作执行日期：2026-09-02
> 需求分支：`feature/issue_req-1788169528204`

## 1. 需求理解与边界

本任务的目标不是把三个 Argus 部署实例做成一个「总账户」，而是让运维能在一屏内看清三个独立实验体的运行、配置与数据状态。需求级文档反复强调三个实例的阈值（5bp、3bp、3bp）、仓位上限（15、26+8、246）和下单张数（1、1、10）均不同；因此跨实例的信号数、张数、胜率、权益和盈亏不具有可加性。总览的“全部实例”模式只能并排观察，不能提供任何合计 KPI。

任务说明要求两个新页面和菜单收敛：

1. `/argus-dashboard`：共享全局实例选择。全部实例模式是三实例状态表；单实例模式才展示运行状态、KPI、权益、触发结果、最近信号、参数摘要和数据健康。
2. `/argus-instances`：实例卡片、参数对比矩阵（差异高亮）、配置分域说明、运行控制可达性说明，并显式暴露参数版本漂移与重复实例键告警。
3. `ManagerShell.tsx`：Argus 入口集中到一个菜单组；全局实例选择在所有 Argus 页面保持。
4. 补页面与新增接口的权限资源。

非目标同样决定了界面形态：本任务的总览不提供参数编辑、不提供热加载/进程控制；整个需求也明确不做 `start / stop / restart` 的远程控制。因而卡片和总览页即使发现漂移，只显示状态与原因，不能借此加入一个“修复”按钮。

### 2.2 已存在的数据与接口

1. `server/service/argus_config/overview.go` 的 `InstanceOverview` 已把注册信息、published 版本、Redis 心跳和本实例内的漂移判断聚合为单一视图；`server/service/argus_config/dto/dto.go` 的 `InstanceRuntimeDTO` 有 `publishedVersion`、`runningVersion`、`effectState`、`duplicateInstanceKeys` 等字段。它避免前端按三个实例循环拉六次大快照，更保证漂移口径和 r7 参数页一致。
2. `server/manager-api/pkg/argus_config/argus_config.go` 已注册 `GET /argus-config/instance-overview`；`client/manager/src/components/argus/argus-instance.api.ts` 已有对应类型和 `effectStateMeta`。该接口只返回状态元数据，不包含会话或凭证。
3. `server/service/argus_event/stats.go` 的 `GetInstanceSummary` 明确逐实例出行且不合计，`GET /argus-event/instance-summary` 返回信号、变体、净仓、权益与已实现盈亏；`GET /argus-event/equity-curve` 的权益点真实字段是 `time`（非 `ts`）。总览 API 类型原有草稿与服务端字段不一致，本轮已改正为 `time/upl/minEquity/maxEquity/samples`，避免前端权益图无数据。
4. `GET /argus-event/gate-stats`、`GET /argus-event/signals`、`GET /argus-event/timeline` 分别用于结果分布、最近事件流和双源 1m K 线覆盖率。所有 `argus-event` 时间均是本地墙钟串，图表使用 `wallClockToChartTime` 保持同一刻度口径。
5. r12 已封装 `LightweightChart` 与深色主题；总览权益图复用该组件和 lightweight-charts 5 的 `LineSeries`，没有引入第二个图表库。
6. `client/manager/src/components/argus/instanceScope.ts` 已是跨组件树的 `useSyncExternalStore`：实例选择写入 `localStorage` 并广播。`ManagerShell.tsx` 已在 Argus 路由上显示 `ArgusInstanceSelector`，而行情、复盘和参数页也已使用同一 scope。这个事实使“全局选择持续保持”无需重复实现。
7. `client/manager/src/app/(console)/argus-config/params/catalog.ts` 的 `PARAM_GROUPS/readParam/formatParamValue` 是配置快照到真实 properties 键与 DB 落点的唯一映射。账户级参数需要 `riskIndex`，不能只读取第一个账户。
8. 菜单现有增量已将总览、实例对比、行情、复盘、回测、寻优和参数页放入 `Argus 管理`；快捷入口也增加总览。工作区还有其他任务未提交的变化，本轮保留而不覆盖这些入口。

### 2.3 权限现状

前置 r7/r9/r12/r13 已各有 `权限资源.sql`。其中 r7 登记配置读取接口，r9 登记 `argus-event` 的汇总/权益/信号接口，r12/r13 补其各自页面或行为。本任务真正新增且前置 SQL 未登记的是 `GET /argus-config/instance-overview`，另有两个页面资源。现有任务的统一惯例是 SQL 用 `@role_id = 1` 作为待确认模板值、并要求执行人确认角色主键；本任务没有收到可授权的实际 role_id，不能擅自执行或猜测角色。

## 3. 方案比较和取舍

### 3.1 总览数据来源

**方案 A：新增一个 dashboard 专用的大型后端接口。** 该方案可把所有面板一次返回，但会重复 r1/r9 的聚合口径，并把权益、K 线、事件和心跳的更新频率硬耦合；还需要新增后端测试与权限资源。

**方案 B：前端逐实例拉 `published` 与 `runtime/status` 后自行拼接。** 这会在三个实例下产生多次往返，且很容易在前端重新写出“已发布 vs 心跳”的漂移规则，和 r7 页面分叉。

**最终采用方案 C：复用 `instance-overview` + r9 的独立读接口。** `instance-overview` 是轻量状态主源；`instance-summary` 保持跨实例不求和；锁定单实例后才追加权益、结果分布、事件流、快照与覆盖率请求。非关键面板采用 `Promise.allSettled`，任一辅助查询失败不会抹掉心跳/版本状态，并在页面明示缺失数据。10 秒轮询与心跳 5 秒上报、15 秒 TTL 相配。

### 3.2 全局选择器

**方案 A：每个页面单独放 Select 并将值各自写 localStorage。** 虽能记住一次选择，却不能让壳层选择器和页面组件立即同步，跨页面回到总览时也容易看见不同范围。

**方案 B：URL query 作为唯一来源。** 可分享链接，但会迫使所有既有 Argus 页重构路由和筛选器，并且“全部实例”在参数/行情页面本来不合法。

**最终采用方案 C：复用现有 `instanceScope.ts` 模块级 store。** 总览和实例页不再复制选择器；`ManagerShell` 根据路由的 `allowAll` 规则控制选择范围。总览表的“查看”动作仅调用该共享 setter，界面立即切为单实例，不跨出全局语义。

### 3.3 参数矩阵

**方案 A：把原型中的阈值、上限、order size 直接硬编码成三列。** 视觉上简单，但一旦发布了新版本或增加币种/账户，展示马上失真。

**方案 B：对每个账户级参数只读取 `accountRisks[0]`。** 这会把 `26+8` 静默成 `26`，恰好违背本任务最重要的实验结构。

**最终采用方案 C：遍历 `PARAM_GROUPS`，从各实例的已发布快照用 `readParam` 读取。** 币种级单元格带 symbol，账户级单元格带账户名，值或作用账户集合不同时整行所有实例单元格以黄色高亮。未发布快照显示“未发布”，不把 `readParam` 的零值当作真实参数。

### 3.4 控制入口

曾考虑在漂移告警旁提供“立即热加载”。该做法被否决：任务明确规定总览不做参数编辑或进程控制，需求级文档也禁止起停实盘。实例页最终只说明“Redis reload 在在线时可达、start/stop/restart 仍是本地脚本且不应在管理端操作”，实际热加载继续留在 r7 单实例参数页。

## 4. 最终落地

### 4.1 总览

- 新增 `client/manager/src/app/(console)/argus-dashboard/page.tsx`，负责选择全部/单实例视图和窗口控件；HTTP 编排下沉至 `hooks/useArgusDashboard.ts`。
- 新增 `api/argus-dashboard.api.ts`，封装实例汇总和权益曲线，并修复权益点字段到服务端实际响应。
- `components/AllInstancesView.tsx` 以注册实例与事件实例的并集建表，保证“已注册但窗口没有事件”及“有事件但未注册”都可见。状态表固定显示心跳、已发/运行版本、策略变体、窗口内信号、净持仓、盈亏，故意没有合计行。
- `components/SingleInstanceView.tsx` 展示运行状态条、四项 KPI、权益图、触发结果分布、最近 12 条只读信号、已发布参数摘要和五项健康清单。K 线双源覆盖率低于 99% 提醒、低于 95% 报错；未观测值显示“—”。
- `components/EquityChart.tsx` 用 lightweight-charts 画每账户相对首个权益的变化百分比，避免不同本金的账户在一条绝对权益线上造成误读。

### 4.2 实例对比

- 新增 `client/manager/src/app/(console)/argus-instances/page.tsx` 与 `hooks/useArgusInstances.ts`。一次读取全量（含停用）实例概览，按实例读 published 快照并拉同窗口逐实例汇总。
- `components/InstanceCards.tsx` 逐卡展示配置来源、心跳、已发/运行版本、构建、变体和窗口态势；漂移、离线和重载错误保持显著。
- `components/ParamMatrix.tsx` 支持“只看有差异参数”，使用真实 properties 键作为辅助识别，不创建编辑控件。
- 页面下方的配置分域说明直接对应真实表/键：`argus_instance`、`argus_config_version` 复合索引、`argus:config:{instanceKey}:*` 和 `argus:heartbeat:{instanceKey}`；可达性说明不宣称跨服务器进程控制可用。

### 4.3 外壳、样式和权限

- `client/manager/src/components/manager-shell/ManagerShell.tsx` 的现有任务增量已经把七个 Argus 入口集中在 `Argus 管理`，并基于共享路由表显示全局选择器。本轮以该实际增量为基础，未将其他任务的回测/寻优入口回退。
- `client/manager/src/app/globals.css` 增加总览/实例页的状态、矩阵、健康清单和响应式布局。复用项目暗色变量、Argus 面板和字体风格，不引入页面私有主题或图表依赖。
- 新增 [`doc/module/r15-27b9e2f39a/权限资源.sql`](../权限资源.sql)：幂等新增实例概览接口和两个页面资源，并以 `@role_id` 做幂等绑定。依赖前置 r7/r9 SQL 的已有接口资源；因为没有被授权的实际 role_id，本轮未执行 SQL。

## 5. 影响和兼容性

1. 后端无变更、无表迁移；所有页面读取的接口均已由前置任务提供。不会影响下单、策略判定或现有 `trade-backtest-runs`。
2. `instanceScope` 的空字符串仍代表全部实例。行情和参数页仍由壳层的 `allowAll=false` 自动落到具体实例，防止阈值线、净仓或发布误跨实例。
3. 统计窗口相对**已入库数据末尾**计算而不是本机当前时间，适配当前主数据是历史回灌的事实；“今日/近 1 天”在页面表示最新数据锚点前的 24 小时，避免当前日期远晚于回灌数据而出现误导性的全空页。
4. 事件汇总没有数据时，实例卡片仍可由注册/心跳接口显示；矩阵没有快照时明确显示“未发布”。这两种缺失不被转换为 0。

## 7. 剩余风险与测试交接

1. **权限执行前确认角色。** `权限资源.sql` 的 `@role_id = 1` 只是项目现有 SQL 的模板默认值，部署前必须由权限管理员替换/确认。还要按 r7/r9 的前置顺序执行，确保复用的读接口资源已存在。
2. **真实环境验收。** 需要 manager-api 能访问 MySQL 与 Redis，并使用有上述资源的登录角色。建议依次访问总览的全部实例模式、切入每个实例、切到实例对比；观察重复键、离线和漂移是否按 `instance-overview` 原样出现。
3. **数据样本。** 使用需求指定的 8/18–8/21 回灌数据时，确认总览的近 1 天窗口以最新数据末尾而非今天的机器时间锚定；单实例权益、信号流和 K 线覆盖率要可见。无数据时应是明确空状态而非 0。
4. **视觉复核。** 浏览器可用后，应以桌面宽度验证三列实例卡、矩阵横向滚动与差异高亮；以 1120px/760px 验证 KPI、健康清单和可达性说明的单列折行。当前没有浏览器绑定是本轮唯一未完成的自验方式。
