### 6.1 后果与失败链路（已逐层查证代码，非推测）

`loadCurrent` 先读 Redis 快照，未命中（`goRedis.Nil`）则回落到数据库：

```
runtimeconfig.Initialize            (runtime.go:62)
  └─ loadCurrent                    Redis 无快照 → 回落 DB
      └─ loadPublishedSnapshot      (runtime.go:253)
          └─ repo.FindPublished()   service/argus_config/repository/repository.go:41
              └─ First(&version)    空表 → gorm.ErrRecordNotFound
      → "restore config snapshot from database: record not found"
  → initialization.Init() 返回 error → cmd.go log.Fatalf → 进程退出
```

即：**现在启动 argus_single 会在加载运行时配置处直接退出**，现象与「缺 `sqlconn`」时类似但原因不同
（这次 DB 连得上，是库里没有已发布的配置版本）。

### 6.2 这不是本次迁移引入的

该失败链路只涉及 `runtimeconfig` + `argus_config*` 表，全部是**目标仓库既有能力**
（commit `453e52a` 的产物），与本次迁入的趋势闸/偏离采样代码无关。迁移前的基线同样起不来。

### 6.3 本任务不代为修复（受 §5 约束 9 明确限制）

主文档 §5 约束 9 写明：「**不把 `application_1/2.properties` 里的账户参数导入 MySQL `argus_config` 表**。
属性文件与 DB 配置的对账、迁移是独立任务」。填数据正是该独立任务的内容，故本轮**未执行**
`server/manager-api/cmd/argus-config-import`，也未向生产库写入任何数据（本轮对该库只做了 `SELECT`/`SHOW`）。
