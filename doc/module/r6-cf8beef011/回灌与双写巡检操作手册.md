# argus_single 历史回灌与双写一致性巡检 · 操作手册

> 任务：`r6-cf8beef011` · 需求：`req-1788169552180`
> 工具：`server/manager-api/cmd/argus-event-import`
> 适用期：JSONL/MySQL 双写期，至 `eventstore.JSONLDualWriteUntil = 2026-12-01`

---

## 1. 一句话

一个二进制干两件事：把历史 JSONL 回灌进事件库（`--apply`），和每天比对 JSONL 与
MySQL 有没有对齐（`--audit`）。两件事共用同一份转换代码与同一个 `event_hash`，
所以巡检发现的缺口可以用同一个命令补上。

**历史 JSONL 是只读真源，本工具从不修改、移动或删除任何原文件。**

---

## 2. 目录 → 实例映射（回灌的前提）

实例归属**只能按来源目录判断**：`8.18-8.21剧烈上涨` 与 `8.18-8.21剧烈上涨-实例2`
是两台机器上同名日期的文件，两边都有叫「账户A-…」的标签但指向不同的真实账户。

| 来源目录 | 实例键 | properties | 账户 |
|---|---|---|---|
| `logs/argus_single/events-0702` | `argus-single-roc` | `application_1.properties` | 2 |
| `logs/argus_single/7.10-datas` | `argus-single-roc` | 同上 | 2 |
| `logs/argus_single/7.17-datas` | `argus-single-roc` | 同上 | 2 |
| `logs/argus_single/7.27-datas` | `argus-single-roc` | 同上 | 2 |
| `logs/argus_single/8.8-datas` | `argus-single-roc` | 同上 | 2 |
| `logs/argus_single/8.10-12-dev_sample` | `argus-single-roc` | 同上 | 2 |
| `logs/argus_single/8.18-8.21剧烈上涨` | `argus-single-roc` | 同上 | 2 |
| `logs/argus_single/8.18-8.21剧烈上涨-实例2` | `argus-single-ives` | `application_2.properties` | 1 |

`logs/argus_single/` 下的其余目录（`ChatExport_*`、`dc_files`、`一键平仓` 等）
不含 `events-<date>.jsonl`，工具会自动忽略。

`application.properties`（实例键 `argus-single-1`）目前没有任何历史事件目录，
它的账户 uid 与 `application_1.properties` 不同，**不要拿它去回灌 roc 的目录**。

## 3. 回灌（一次性）

从 `server/manager-api` 目录跑；不带 `--dsn` 时读该目录 `configs/application.properties`
的 `sqlconn`。

```bash
cd server/manager-api

# 实例1（两个账户）：七个历史快照目录，日期互相重叠，靠 event_hash 去重
go run ./cmd/argus-event-import \
  --instance argus-single-roc \
  --config ../argus_single/configs/application_1.properties \
  --source ../../logs/argus_single/events-0702 \
  --source ../../logs/argus_single/7.10-datas \
  --source ../../logs/argus_single/7.17-datas \
  --source ../../logs/argus_single/7.27-datas \
  --source ../../logs/argus_single/8.8-datas \
  --source ../../logs/argus_single/8.10-12-dev_sample \
  --source '../../logs/argus_single/8.18-8.21剧烈上涨' \
  --report ../../doc/module/r6-cf8beef011/report/一致性巡检-argus-single-roc.md \
  --apply

# 实例2（单账户）
go run ./cmd/argus-event-import \
  --instance argus-single-ives \
  --config ../argus_single/configs/application_2.properties \
  --source '../../logs/argus_single/8.18-8.21剧烈上涨-实例2' \
  --report ../../doc/module/r6-cf8beef011/report/一致性巡检-argus-single-ives.md \
  --apply
```

- **不加 `--apply` 就是 dry run**：扫描 + 出报告，一行都不写库。第一次跑先这样。
- 回灌**幂等**：重跑同一批目录，`新插入=0 / 已存在=全部`。
- 回灌行带 `source=2`、`config_version=0`，与直写行（`source=1`）在库里可区分。

## 4. 双写期每日巡检

只比对不写库，跑**昨天**（今天的 JSONL 还在追加，比对会假报缺失）：

```bash
cd server/manager-api
DAY=$(date -v-1d +%F)          # Linux: DAY=$(date -d yesterday +%F)
go run ./cmd/argus-event-import \
  --instance argus-single-roc \
  --config ../argus_single/configs/application_1.properties \
  --source /data/program/app/argus_single/logs \
  --since "$DAY" --until "$DAY" \
  --report "/data/argus_audit/$DAY-argus-single-roc.md" \
  --audit
```

`--source` 指向该实例运行机上 `log.dir` 的实际路径（properties 里是 `./logs/`，
即 `<部署目录>/logs`）。JSONL 在哪台机器，巡检就在哪台机器跑，或者先同步过来。

**退出码**：一致 = 0；发现缺失行或「库里有整天数据而 JSONL 没有」= 2。
挂 cron 时直接用退出码告警，不用解析报告：

```cron
30 1 * * * cd /data/program/app/manager-api && ./argus-event-import --instance argus-single-roc \
  --config ./configs/application_1.properties --source /data/program/app/argus_single/logs \
  --since $(date -d yesterday +\%F) --until $(date -d yesterday +\%F) \
  --report /data/argus_audit/$(date -d yesterday +\%F)-roc.md --audit || echo "argus 事件双写出现缺口"
```

发现缺失后补齐：**同一条命令把 `--audit` 换成 `--apply`**。缺的行会被插进去，
已有的行被 `event_hash` 吃掉，不会重复。

## 5. 报告怎么读

| 章节 | 看什么 |
|---|---|
| 1 源文件读取 | 坏行必须是 0。非 0 说明 JSONL 被截断或写坏 |
| 2 逐日回灌 | `重复` 是来源目录快照互相重叠的正常现象；`新插入 / 已存在` 是幂等性的直接证据 |
| 3 字段可用性 | 下游按天查历史前先看这张表。`equity` / `net_size` 在 2026-07-21 之前全是未知，把它读成 0 会造出假数据 |
| 4 一致性 | **`缺失` 是唯一需要动作的列。** `多出` 只在来源目录没覆盖那一天时才正常 |
| 5 字段适用性异常 | 按设计文档 §6.6 矩阵判定「应有而缺」，只报数不拦截 |

## 6. 会报错停下的几种情况

| 情况 | 行为 | 处理 |
|---|---|---|
| 事件里的 account 标签在 properties 里查不到 | **拒绝导入并报错**，列出标签 | 补 `trade.accountN.name/uid`。**不要猜 uid**——uid 从来没进过事件，猜错会让整段归因静默错位 |
| `trade.accountN.uid` 为空 | 报错退出 | 同上 |
| 实例键没登记进 `argus_instance` | 报错退出 | 先跑 `argus-config-import` 注册实例（注册表整个为空时放行，避免自举死锁） |
| `--instance` 与 properties 里的 `argus.instance.id` 不一致 | 只告警、按 `--instance` 归属 | 历史目录可能来自改名之前的部署，归属由人判断 |
| `sqlconn` 为空且没给 `--dsn` | 报错退出 | 从 `server/manager-api` 跑，或显式给 `--dsn` |

## 7. 安全

- 报告里不含任何凭证、不含账户标签，只有路径、日期与计数。
- `--dsn` 会出现在 shell history 与进程列表里：生产环境用 `configs/application.properties`
  的 `sqlconn`，不要在命令行贴 DSN。
- `logs/` 与 `configs/` 含真实生产凭证，任何测试资产与文档都不得引用其内容。
