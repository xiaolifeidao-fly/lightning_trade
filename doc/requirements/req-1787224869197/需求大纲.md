# lightning_trade 和 BADelay500W 合并

## 需求背景与目标

- 当前 `lightning_trade` 已有 `server/argus_single`，但该目录现有实现不再需要，应由同级项目 `../BADelay500W/argus_single` 完整替换；`lightning_trade` 的其他服务端和客户端模块继续保留。
- `BADelay500W/argus_single` 的账户、交易、风控、监控币种、Telegram 等参数主要维护在 `configs/application.properties`，会话凭证维护在 `configs/session.json`，修改依赖人工编辑服务器文件。
- 当前项目已有 MySQL/GORM、Redis、Go Manager API 和 Next.js 管理端。目标是将 Argus 配置结构化保存到数据库，通过管理端维护和发布，并把已发布配置同步到 Redis，使运行中的 Argus 可安全热加载。
- `session.json` 中 Cookie、Token、Sentry 等运行态会话数据也需要入库，并支持 Argus 自动刷新回写。
- 管理端除配置维护外，还需要展示 Argus 在线状态、当前配置版本，并提供启动、停止、重启和热加载操作。

## 范围与不做的事

### 本次范围

1. 删除 `server/argus_single` 当前业务实现，以 `../BADelay500W/argus_single` 完整替换，并适配当前仓库公共模块和构建方式。
2. 仅迁移 `../BADelay500W/argus_single/configs/application.properties` 这一份主配置，不迁移 `application_1.properties`、`application_2.properties` 和 `dev.properties`。
3. 建立单实例 Argus 配置、交易账户、账户风控、监控币种、全局参数、通知配置和运行态会话的数据库模型。
4. 在 `server/service`、`server/manager-api` 增加配置维护、校验、发布、Redis 快照同步和运行控制接口。
5. 改造 Argus 启动和运行链路：启动时加载数据库/Redis 中的生效配置，运行中订阅 Redis 配置版本变更并原子热加载。
6. 将 Cookie、Token、Sentry 等会话信息从文件迁入数据库，并允许 Argus 更新后安全回写。
7. 在 `client/manager` 增加 Argus 配置、运行状态和启动/停止/重启/热加载页面。
8. 导入现有 `application.properties`、`session.json` 并完成端到端回归。

### 暂不纳入

- 不保留 `lightning_trade/server/argus_single` 当前独有的 AI 开仓、AI 平仓和 BTC 市场数据实现。
- 不迁移 `../BADelay500W/argus_single_AI`。
- 不迁移或维护 `application_1.properties`、`application_2.properties`、`dev.properties`，首版只支持一套 Argus 实例配置。
- 不在本轮实施代码、数据库或任务面板写入；本轮只维护需求大纲和拆解预览。
- 不把数据库连接、Redis 连接等读取远端配置所必需的引导参数存入数据库或 Redis。
- 暂不设计多机器、多实例或集群编排；运行控制任务先按 Manager API 与 Argus 同机、调用受限启停脚本的默认方案拆解，后续实施时可根据实际部署拓扑调整实现。

## 关键约束

- `server/argus_single` 采用完整替换，不进行旧 Argus 业务代码合并；`server/common`、`server/service`、`server/manager-api`、`client/manager` 等其他项目模块不得因替换被删除。
- BADelay 源码中的 `badelay500w/common` 模块路径必须适配为当前仓库的 `common`，并统一 Go 版本、依赖和构建脚本。
- MySQL 是配置与会话的持久化事实来源；Redis 保存当前发布版本、完整运行快照、版本号、心跳和控制消息，用于快速读取和热加载，不作为唯一持久化来源。
- 配置发布采用“数据库事务保存成功 → 生成完整快照 → 写入 Redis → 发布版本变更消息”的顺序；任一步失败不得覆盖上一有效版本。
- Argus 热加载必须先完整解析和校验新快照，再原子替换运行配置；失败时继续使用旧配置并上报错误，不能在交易中使用半套新旧配置。
- 交易账户包含 API Key、Secret、Passphrase、账号密码、Google Auth Key、Cookie、Token、Sentry 和 Telegram Token 等敏感信息；数据库加密、Redis 快照保护、接口脱敏、日志过滤和页面遮罩必须形成完整链路。
- 运行态会话与静态账户配置分开建模，Argus 可回写会话，但不能通过普通列表接口返回完整值。
- Redis 现有入口位于 `server/common/middleware/redis/RedisClient.go`，当前只封装基础 KV，需要补充带 context 的 Set/Get、Publish/Subscribe、心跳 TTL 和错误返回能力。
- 启停脚本已有真实落点 `server/argus_single/script/start.sh`、`stop.sh`；进程控制必须使用受限命令映射，不能让管理端提交任意 shell 命令。
- 管理端 HTTP 请求必须使用 `client/manager/src/utils/axios.ts`，页面遵循 Next.js App Router、Ant Design 和 class DTO/API 分层。
- 当前任务面板没有可用里程碑和模块，因此预览中的里程碑、模块只能标记为“未选择（现有无选项）”。

## 任务详情与验收标准

### 任务 1：使用 BADelay500W 完整替换 argus_single

**目标**

删除当前 `server/argus_single` 业务实现，将 `../BADelay500W/argus_single` 作为唯一 Argus 主线迁入，其他 lightning_trade 模块保持不变。

**范围**

- 迁移 BADelay 的事件日志、健康检查、价格与账户监控、信号调度、平仓、移动止盈和风险控制。
- 不迁移二进制、PID、日志、运行数据及多余配置文件。
- 适配 `common` 模块路径、Go 版本、依赖和构建部署脚本。
- 删除当前 Argus 独有 AI 开平仓和 BTC 市场数据代码，不影响仓库其他服务。

**验收标准**

- `server/argus_single` 源码与 BADelay 主线功能一致并可独立编译。
- BADelay 已有单元测试可运行，初始化顺序覆盖路由、监控、交易、会话和通知。
- 不再残留旧 Argus AI 业务代码或 `badelay500w/*` 导入。
- `server/common`、`server/service`、`server/manager-api`、`client` 等目录不因替换丢失。

### 任务 2：建立单实例 Argus 配置与会话数据库模型

**目标**

将 `application.properties` 和 `session.json` 中需要维护的数据结构化保存到 MySQL。

**范围**

- 在 `server/service/argus_config/repository` 建立单实例配置、账户、账户风控、币种、通知和会话模型。
- 只支持一套主配置，可保留草稿版本与唯一已发布版本，不设计多个运行实例。
- 会话与静态账户分表，记录更新时间、有效状态和关联账户。
- 敏感字段采用应用层加密或项目确认的等效方案，增加必要唯一索引和状态约束。

**验收标准**

- 模型可无损表达主 `application.properties` 和 `session.json` 的有效字段。
- 数据库只能存在一个当前已发布版本，但历史版本可追溯和回滚。
- Secret、Password、Google Auth Key、Cookie、Token、Sentry、Telegram Token 不以可直接识别的明文存储。
- GORM 迁移可重复执行且不破坏已有数据。

### 任务 3：实现配置管理 API 与 Redis 发布通道

**目标**

提供数据库配置维护、完整校验、版本发布，以及数据库到 Redis 运行快照的安全同步。

**范围**

- 新增 `server/service/argus_config` DTO、Repository、Service 和 `server/manager-api/pkg/argus_config` Handler。
- 支持配置、账户、风控、币种、通知和会话的维护与脱敏查询。
- 扩展 `server/common/middleware/redis`，增加显式错误返回、JSON 快照、版本键、Publish/Subscribe 和心跳 TTL 能力。
- 发布时事务保存数据库，生成完整快照并写入 Redis，最后发布版本变更消息。
- 敏感字段查询脱敏，留空更新不覆盖原值，发布动作记录操作者和版本。

**验收标准**

- 非法参数、缺少账户、无效币种或敏感字段处理失败时不能发布。
- Redis 写入或通知失败时，旧版本仍是唯一有效运行版本。
- API 不返回敏感明文，Redis 快照具有访问隔离、有效版本号和完整性校验。
- 发布成功后可从数据库与 Redis 查询到一致的版本和快照摘要。

### 任务 4：实现 Argus 配置热加载与会话回写

**目标**

让运行中的 Argus 订阅 Redis 配置变更，在不中断进程的情况下安全切换配置，并将刷新后的会话写回数据库。

**范围**

- 启动时读取 Redis 当前快照，缓存缺失时从数据库恢复并重建 Redis 快照。
- 订阅配置版本频道，加载新快照并完成结构、关联、范围和敏感字段解密校验。
- 采用原子配置引用或等效同步机制切换账户、风控、币种、Telegram 等运行参数。
- 明确不能安全动态替换的字段；此类字段发布后标记为需要重启，不强行热加载。
- 将登录刷新产生的 Cookie、Token、Sentry 等会话按账户回写数据库，并同步必要的 Redis 会话缓存。

**验收标准**

- 可在 Argus 运行中修改并发布可热加载字段，无需重启即可使用新版本。
- 新配置解析或校验失败时继续使用旧版本，并向状态接口记录失败版本和原因。
- 并发监控和交易读取配置时不存在半更新、空引用或数据竞争。
- 会话刷新后数据库记录更新，重启后可恢复使用，敏感值不进入普通日志。

### 任务 5：实现 Argus 心跳与安全运行控制

**目标**

让管理端可查看 Argus 在线状态、版本和错误，并安全执行启动、停止、重启及主动热加载。

**范围**

- Argus 周期性向 Redis 写入带 TTL 的心跳、PID、启动时间、当前版本、最后热加载结果和健康状态。
- Manager API 提供运行状态查询、启动、停止、重启和重新加载接口。
- 复用并加固 `server/argus_single/script/start.sh`、`stop.sh`，增加明确的 restart/control 适配层。
- 控制接口只允许固定动作，校验进程路径/PID，串行化控制请求并记录操作结果。
- 停止与重启优先优雅退出，给监控关闭和状态持久化留出时间。

**验收标准**

- 管理端可区分运行中、已停止、启动中、停止中、异常和心跳超时状态。
- 重复启动不会产生多个 Argus 进程，停止不会误杀其他进程。
- 启停、重启和热加载均返回可追踪结果，失败后状态与真实进程一致。
- 未授权用户不能调用控制接口，接口参数不能形成任意命令执行。

### 任务 6：新增管理端 Argus 配置与运行控制页面

**目标**

在 `client/manager` 中完成配置维护、发布、热加载和进程控制，替代文件及命令行操作。

**范围**

- 新增 `argus-config` 页面、API class、组件和 Hooks，并接入 `ManagerShell` 导航。
- 页面覆盖账户、风控、监控币种、通知、会话状态、配置版本与发布记录。
- 顶部展示在线状态、当前版本、启动时间和最后热加载结果。
- 提供发布并热加载、重新加载、启动、停止、重启按钮；停止和重启需二次确认。
- 敏感字段默认遮罩，只允许输入新值覆盖，不回显完整历史值。

**验收标准**

- 用户无需编辑服务器文件即可完成主配置和会话相关维护。
- 发布后可看到目标版本、热加载结果和当前运行版本是否一致。
- 进程按钮根据实时状态正确禁用，重复点击不会并发执行相同控制动作。
- 所有请求使用 `@utils/axios`，页面数据和表单具有严格 TypeScript 类型。

### 任务 7：导入主配置和会话并完成端到端验收

**目标**

将 BADelay 主 `application.properties` 和 `session.json` 安全迁入数据库，验证配置管理、Redis 热加载和运行控制链路可上线。

**范围**

- 提供一次性导入工具或受控导入流程，只读取主 `application.properties` 和 `session.json`。
- 导入前校验字段映射，敏感值不输出到控制台、日志和验收报告。
- 验证数据库发布、Redis 快照、Argus 热加载、会话回写、心跳、启动、停止和重启。
- 回归多账户、监控信号、交易方向、仓位上限、止盈止损、Telegram、事件日志和健康接口。

**验收标准**

- 导入可重复演练，不重复创建当前生效配置，也不读取其他 properties 文件。
- 导入后字段与源文件逐项一致，敏感字段全链路无明文泄露。
- 合法配置热加载成功，非法配置不影响旧版本运行。
- 在线状态和控制结果与真实进程一致，核心测试、构建和一次完整启动验证通过。

## 需求级验收标准

1. `server/argus_single` 已由 BADelay500W 主实现完整替换，旧 Argus 业务代码删除，其他 lightning_trade 模块保持不变。
